# Growth Plan: 23★ → 1000★ (oss-health-scan)

## Движок роста этого репо
Инструменты разработчика растут не рекламой, а **тремя петлями**: запуск → полезность в CI → бейджи в чужих README. У тебя есть редкое ядро: живая data-история (State of npm Abandonment) + рабочий CLI. Это и продаём.

## 1. Запуск (одна неделя, последовательно)
1. **npm 1.7.0 жив** ✅ — можно ссылаться на `npx oss-health-scan --paranoid`.
2. **Вторник 15:00 UTC — Show HN** (черновик docs/promo/HN_POST_DRAFT.md):
   - Заголовок: `Show HN: I scanned the top npm packages — 20 of 123 are abandoned but pull 297M downloads/week (CLI to check yours)`
   - Число 297M в заголовке — это hook. Первый комментарий — ты сам: ссылка на дашборд + как воспроизвести.
   - НЕ постить в выходные. Отвечать на каждый комментарий первые 6 часов.
3. **Тот же день — r/programming** (REDDIT_POST_DRAFT.md): заголовок без «Show», история про abandonment-исследование. r/webdev + r/node кросспост на следующий день.
4. **dev.to статья** (DEVTO_ARTICLE_DRAFT.md) — длинная, с картинками дашборда, теги: #npm #security #opensource #javascript.
5. **Awesome-листы** (неделя 2): PR в awesome-nodejs, awesome-npm, awesome-security. Каждый принятый PR = постоянный входящий трафик.

## 2. Петля полезности (удержание)
- **GitHub Action по умолчанию пишет SARIF** → проекты встраивают скан в CI → каждый CI-лог = реклама.
- **Бейдж** `![OSS Health](https://img.shields.io/endpoint?url=…/badge/<pkg>)` — верхний блок README у других. Нужен деплой badge-worker (см. ниже).
- **--paranoid в трендах**: Sha1-Hulud/npm-атаки в новостях → постить «проверь свои зависимости одной командой» ровно в дни новых supply-chain инцидентов (у нас мониторинг таких волн идёт постоянно).

## 3. Петля бейджей (вирусность)
- Деплой `badge-worker/` на Cloudflare (operator step: `npx wrangler deploy`).
- README-секция «Get your badge» (уже спланировано): каждый встроенный бейдж = бесплатный баннер.
- Дашборд публичный и обновляется каждые 6ч — ссылка на него из каждого поста.

## 4. Что не делать
- Не покупать/не фармить звёзды — github ловит и это убивает заявку и репутацию.
- Не спамить в issues чужих репо. Только PR с реальными фиксами (это уже есть и это сильно).
- Не постить одновременно во все каналы — волна по одному каналу в день, иначе модераторы режут.
